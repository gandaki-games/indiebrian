Game Distribution Platform

Flutter Dart Khalti API

A mobile storefront prototype built to streamline game discovery, purchasing, and downloading for gamers in Nepal. The application integrates secure local payment gateways, two-factor mobile authentication, and personalized library synchronization.

System Architecture & Workflow

1. Client-Side Presentation (Flutter & Dart)

The frontend uses cross-platform reactive state management to maintain synchronous UI updates across the game store, search filters, wishlist, and library views.

2. Authentication & Verification Subsystem

User identity is secured using phone-number verification via One-Time Passwords (OTP). Upon submitting a mobile number, the client initiates a request to the backend service to dispatch an SMS payload containing a cryptographically generated token.

3. Payment Gateway Integration (Khalti SDK/API)

Transaction flows are handled through a Khalti wallet integration designed for local currency operations.

Core Logic Specifications

Authentication & Phone OTP Validation

The login flow relies on time-sensitive OTP verification to ensure verified user credentials before facilitating monetary transactions:

  • User submits their local mobile phone number.
  • System generates a 6-digit numeric token with a 300-second expiration lifecycle.
  • User inputs the received OTP; upon verification, a JWT user session token is generated and stored in secure encrypted client storage.

Khalti Transaction Handling Sequence

[User Checkout] → [Initiate Khalti Payment Intent]
  → [Verify Khalti PIN & OTP on Gateway]
  → [Receive Payment Token from Khalti Server]
  → [Backend Verification API Call (`/api/v2/payment/verify/`)]
  → [Database State Update: Update User Library & Add Order Record]
  → [Trigger Game Asset Download Authorization]

Digital Rights & Download Management

  • Entitlement Checking: Before granting access to binary download files, the backend queries the database for an active ownership record associated with the user ID.
  • Secure Tokenized Downloads: Once ownership is validated, the server responds with a temporary, signed download URL preventing direct unauthorized link sharing.
